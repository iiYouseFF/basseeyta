  1. 1 — Register Customer (creates customerToken + customerId)
    POST {{base}}/auth/register — Headers: Content-Type: application/json (no Auth)
    Body (raw JSON): {"name":"Postman Customer","phone":"01000000111","governorate":"القاهرة","city":"القاهرة"}
    → Response {data:{token,user:{id,phone}}} — in Postman Tests tab add:
    pm.environment.set("customerToken", pm.response.json().data.token); pm.environment.set("customerId", pm.response.json().data.user.id); pm.environment.set("customerPhone", pm.response.json().data.user.phone);
    Phone is normalized to +20…; duplicates return 409 Phone already registered — use a new random phone (01000000xxx).
  2. 2 — Register Technician (creates techToken + techPhone)
    POST {{base}}/auth/technicians/register — no Auth
    {"fullName":"Postman Tech","phone":"01000000112","governorate":"القاهرة","specialty":"سباكة"}
    → {data:{token,technician:{phone,id}}} — Tests:
    pm.environment.set("techToken", pm.response.json().data.token); pm.environment.set("techPhone", pm.response.json().data.technician.phone);
    Technicians are stored by phone as ID; same phone check as customers. If you re-use phone, expect 409.
  3. 3 — Customer Creates Order ( service-request )
    POST {{base}}/service-requests — Headers: Authorization: Bearer {{customerToken}}
    {"userId":"{{customerId}}","userName":"Postman Customer","userPhone":"{{customerPhone}}","userGovernorate":"القاهرة","title":"سباكة - تسريب مياه","description":"تسريب تحت الحوض","budget":"500","serviceType":"plumbing"}
    → Returns {data:{id,request:{status:"pending"}}} — Tests:
    pm.environment.set("requestId", pm.response.json().data.id);
    Required fields per src/modules/service-requests/serviceRequests.routes.ts:10: userId,userName,userPhone,userGovernorate,title,description,budget,serviceType. Optional: userRegion,scheduledDate,images. Auth is required (401 otherwise).
  4. 4 — Technician Creates Offer on that Order
    POST {{base}}/service-requests/{{requestId}}/offers — Headers: Authorization: Bearer {{techToken}}
    {"price":450,"technicianName":"Postman Tech","message":"جاهز خلال 30 دقيقة + ضمان شهر"}
    → Returns {data:{id, requestId, technicianId, price, status:"pending"}} — Tests:
    pm.environment.set("offerId", pm.response.json().data.id);
    Only userType: technician tokens can do this (403 Only technicians…). Server also emits /requests → new_offer and /notifications → notification. You can verify via GET {{base}}/service-requests/{{requestId}}/offers (no auth needed, returns list).
  5. 5 — Customer Lists Offers (confirm offer exists)
    GET {{base}}/service-requests/{{requestId}}/offers — no Auth required
    Returns array sorted desc. Should contain your {{offerId}}. Also try GET {{base}}/service-requests?userId={{customerId}} or GET {{base}}/service-requests/{{requestId}} to see hasOffers:true.
  6. 6 — Customer Accepts Offer (the "order accepted" moment)
    PATCH {{base}}/offers/{{offerId}} — Headers: Authorization: Bearer {{customerToken}}
    {"status":"accepted"} — also supports {"status":"rejected"}
    → Returns {data:{offer, request:{status:"accepted", technicianId, acceptedPrice}, chatRoom:{id, clientId, technicianId}}} — Tests:
    pm.environment.set("roomId", pm.response.json().data.chatRoom.id);
    This is the transactional step (src/modules/offers/offers.routes.ts:112): offer→accepted, request→accepted, other offers→rejected, chat room + appointment auto-created, notification to tech. Subsequent PATCH /offers/:id with same id is idempotent but will stay accepted.
  7. 7 — Verify side-effects (all after Accept)
    • GET {{base}}/chat/rooms?userId={{customerId}} — Auth: customer token — should list the new roomId (filter by requestId)
    • GET {{base}}/chat/rooms/{{roomId}}/messages?limit=50 — initially []
    • POST {{base}}/chat/rooms/{{roomId}}/messages {"senderId":"{{customerId}}","senderType":"user","message":"مرحبا"} → triggers new_message on socket
    • GET {{base}}/appointments?requestId={{requestId}} or ?userId={{customerId}} — Auth required — shows status:"scheduled" (created in Accept)
    • GET {{base}}/service-requests/{{requestId}} — status:"accepted", acceptedPrice:450
    • Socket: connect /chat with auth:{token: {{customerToken}}}, emit join_room "{{roomId}}", listen new_message
    Socket proof that Accept worked: connect two Socket.IO clients (customer + tech) to /chat with their tokens, both join_room with {{roomId}}, then send_message {roomId, senderId, senderType, message} — both receive new_message via src/socket/index.ts:65. REST POST /chat/rooms/:id/messages also broadcasts the same event.
curl script for Steps 1→7 (copy-paste, sets shell vars) 
BASE=http://basseeyta.duckdns.org
# 1. register customer
CUST_RES=$(curl -s -X POST $BASE/auth/register -H 'Content-Type: application/json' \
  -d '{"name":"Postman Customer","phone":"01000000111","governorate":"القاهرة","city":"القاهرة"}')
echo "$CUST_RES" | python3 -m json.tool
CUST_TOKEN=$(echo "$CUST_RES" | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['token'])")
CUST_ID=$(echo "$CUST_RES" | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['user']['id'])")
CUST_PHONE=$(echo "$CUST_RES" | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['user']['phone'])")
echo "CUST $CUST_ID $CUST_PHONE"

# 2. register technician
TECH_RES=$(curl -s -X POST $BASE/auth/technicians/register -H 'Content-Type: application/json' \
  -d '{"fullName":"Postman Tech","phone":"01000000112","governorate":"القاهرة","specialty":"سباكة"}')
echo "$TECH_RES" | python3 -m json.tool
TECH_TOKEN=$(echo "$TECH_RES" | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['token'])")
TECH_PHONE=$(echo "$TECH_RES" | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['technician']['phone'])")

# 3. create order (service-request)
REQ_RES=$(curl -s -X POST $BASE/service-requests -H "Authorization: Bearer $CUST_TOKEN" -H 'Content-Type: application/json' \
  -d "{\"userId\":\"$CUST_ID\",\"userName\":\"Postman Customer\",\"userPhone\":\"$CUST_PHONE\",\"userGovernorate\":\"القاهرة\",\"title\":\"سباكة - تسريب مياه بالمطبخ\",\"description\":\"تسريب تحت الحوض\",\"budget\":\"500\",\"serviceType\":\"plumbing\"}")
echo "$REQ_RES" | python3 -m json.tool
REQ_ID=$(echo "$REQ_RES" | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['id'])")
echo "REQ $REQ_ID"

# 4. tech creates offer
OFFER_RES=$(curl -s -X POST $BASE/service-requests/$REQ_ID/offers -H "Authorization: Bearer $TECH_TOKEN" -H 'Content-Type: application/json' \
  -d '{"price":450,"technicianName":"Postman Tech","message":"جاهز خلال 30 دقيقة + ضمان شهر"}')
echo "$OFFER_RES" | python3 -m json.tool
OFFER_ID=$(echo "$OFFER_RES" | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['id'])")
echo "OFFER $OFFER_ID"

# 5. list offers (verify)
curl -s $BASE/service-requests/$REQ_ID/offers | python3 -m json.tool

# 6. customer accepts offer  -> creates chat room + appointment
ACC_RES=$(curl -s -X PATCH $BASE/offers/$OFFER_ID -H "Authorization: Bearer $CUST_TOKEN" -H 'Content-Type: application/json' \
  -d '{"status":"accepted"}')
echo "$ACC_RES" | python3 -m json.tool
ROOM_ID=$(echo "$ACC_RES" | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['chatRoom']['id'])")
echo "ROOM $ROOM_ID"

# 7. verify
curl -s -H "Authorization: Bearer $CUST_TOKEN" $BASE/chat/rooms?userId=$CUST_ID | python3 -m json.tool
curl -s -H "Authorization: Bearer $CUST_TOKEN" $BASE/appointments?requestId=$REQ_ID | python3 -m json.tool
curl -s $BASE/service-requests/$REQ_ID | python3 -m json.tool

6 — Extended Reference: REST + Socket.IO Cheat Sheet

    
The full API surface: use this as a compact reference after running the E2E flow above. The automated runner already executes the highlighted path; this card lists every verbatim path + alternative socket flows.

    

      

        
A — REST (works in Postman, curl, any HTTP client)

        
    
          
  1. Set Base URL
    http://basseeyta.duckdns.org  — for local use http://localhost:3000
    2. 
          
  2. Get JWT — two options:
            
    
              Mock OTP (recommended, no Firebase):
    
              POST {{base}}/auth/request-otp {"phone":"01000000101"} → returns {data:{mock:true, verificationId}}
    
              POST {{base}}/auth/verify-otp {"phone":"01000000101","code":"123456","verificationId":"..."} → returns {data:{token, user}} (any 6 digits works)

    
              Direct register (even faster):
    
              POST {{base}}/auth/register {"name":"Test","phone":"01000000111","governorate":"القاهرة"} → returns {data:{token, user}}
    
              Technician: POST {{base}}/auth/technicians/register {"fullName":"Tech","phone":"01000000112","governorate":"القاهرة"}
            
    
          
    3. 
          
  3. Create chat room (idempotent by requestId) — usually auto-created at Accept, but manual works too
    POST {{base}}/chat/rooms — Headers: Authorization: Bearer <token>
    Body: {"clientId":"<user.id>","technicianId":"<tech.phone>","requestId":"req_123","serviceType":"plumbing"}
    → returns {data:{id: roomId}} (reuse requestId returns same room)
    4. 
          
  4. Send message via REST
    POST {{base}}/chat/rooms/:id/messages — Headers: Authorization: Bearer <token>
    Body: {"senderId":"<user.id>","senderType":"user","message":"Hello"} (senderType user | technician)
    → server saves + emits new_message to socket room + creates notification
    5. 
          
  5. Read history
    GET {{base}}/chat/rooms/:id/messages?limit=50 — sorted desc
    GET {{base}}/chat/rooms?userId=<id> — list rooms
    GET {{base}}/chat/rooms/:id/unread?userId=<id>
    PATCH {{base}}/chat/rooms/:id/read Body: {"userId":"<id>"}
    6. 
          
  6. Service Requests & Offers (order lifecycle)
    
            POST {{base}}/service-requests (cust token) — creates pending request
    
            GET {{base}}/service-requests?userId=<id>&status=pending — filter
    
            POST {{base}}/service-requests/:id/offers (tech token) — price etc
    
            GET {{base}}/service-requests/:id/offers — list
    
            PATCH {{base}}/offers/:id {"status":"accepted"} (cust token) — creates chatRoom + appointment
    
            GET {{base}}/appointments?requestId=:id — scheduled
    
            GET {{base}}/service-requests/:id — still pending vs accepted
          
    7. 
        

      

      

        
B — Socket.IO (Postman Socket.IO, or browser)

        
    
          
  1. Postman Socket.IO request
            
      
              
    • Open Postman → New → Socket.IO (if not visible: New → More → Socket.IO)
      • 
              
    • Server URL: http://basseeyta.duckdns.org — keep http:// (not ws://). Postman handles upgrade.
      • 
              
    • Namespace: /chat (for chat), /notifications, /requests
      • 
              
    • Auth: click Headers/Auth → Auth type: Bearer Token or add handshake field: auth.token = <JWT>. In Postman's Socket.IO tab: Auth → add key token value eyJ.... Alternative: Headers → Authorization: Bearer <token>
      • 
              
    • Click Connect — you should see [socket:/chat] connected <id> in server logs (pm2 logs)
      • 
            
    
          
    2. 
          
  2. Join a room
    Event: join_room — Message: "<roomId>" (string, not JSON). Use the ID from POST /chat/rooms or from PATCH /offers/:id → data.chatRoom.id. Click Send. Server logs: joined room:<id>
    3. 
          
  3. Listen
    Add listener for event new_message — Postman: Add listener → Event name new_message — you'll receive:
    {"id":"...","roomId":"...","senderId":"...","senderType":"user","message":"...","createdAt":"..."} for every message in that room (including from REST).
    4. 
          
  4. Send via socket
    Event: send_message — Message (JSON):
    {"roomId":"<roomId>","senderId":"<userId>","senderType":"user","message":"Hello from Postman"}
    → All members in room get new_message instantly. Check GET /chat/rooms/:id/messages to see persistence.
    5.

      • 
            
    
          
    6. 
          
  6. Leave
    Emit leave_room with "<roomId>" to stop receiving.

Troubleshooting
          
    
            
  • Nginx 400 / CORS: Ensure nginx/basita.conf has location /socket.io/ with proxy_set_header Upgrade and Connection "upgrade" (it does). Restart: sudo nginx -t && sudo systemctl restart nginx
    • 
            
  • Uses http:// not https:// — VPS is currently http://basseeyta.duckdns.org (no cert). Don't use wss://.
    • 
            
  • Auth ignored but logged: Server middleware logs [socket] auth failed but still connects (dev). For production, change src/socket/index.ts:19 from return next() to return next(new Error('Unauthorized')) to enforce.
    • 
            
  • Room not found: Socket send_message creates message even if room missing, but REST requires room. Always POST /chat/rooms or accept an offer first.
    • 
            
  • Transport: Postman and browser auto-negotiate polling → websocket. If blocked, force transports:['websocket'] but Nginx must allow upgrade.
    • 
            
  • Order 403 on offer: Only technicians can POST offers. Be sure you use techToken (from /auth/technicians/register).
    • 
            
  • Offer 404 / request not found: The requestId must be the UUID from POST /service-requests data.id (not the placeholder you typed).
    •
