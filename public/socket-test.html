5 — How to Test with Postman (and other external tools)

This page itself is the easiest tester, but you can also reproduce everything from Postman, Insomnia, or any HTTP/WebSocket client. The API is plain Express + Socket.IO 4 — no extra setup.

A — REST (works in Postman, curl, any HTTP client)

  1. Set Base URL
    http://basseeyta.duckdns.org — for local use http://localhost:3000
  2. Get JWT — two options:
    Mock OTP (recommended, no Firebase):
    POST {{base}}/auth/request-otp {"phone":"01000000101"} → returns {data:{mock:true, verificationId}}
    POST {{base}}/auth/verify-otp {"phone":"01000000101","code":"123456","verificationId":"..."} → returns {data:{token, user}} (any 6 digits works)

    Direct register (even faster):
    POST {{base}}/auth/register {"name":"Test","phone":"01000000111","governorate":"القاهرة"} → returns {data:{token, user}}
    Technician: POST {{base}}/auth/technicians/register {"fullName":"Tech","phone":"01000000112","governorate":"القاهرة"}
  3. Create chat room (idempotent by requestId)
    POST {{base}}/chat/rooms — Headers: Authorization: Bearer <token>
    Body: {"clientId":"<user.id>","technicianId":"<tech.phone>","requestId":"req_123","serviceType":"plumbing"}
    → returns {data:{id: roomId}} (reuse requestId returns same room)
  4. Send message via REST
    POST {{base}}/chat/rooms/:id/messages — Headers: Authorization: Bearer <token>
    Body: {"senderId":"<user.id>","senderType":"user","message":"Hello"} (senderType user | technician)
    → server saves + emits new_message to socket room + creates notification
  5. Read history
    GET {{base}}/chat/rooms/:id/messages?limit=50 — sorted desc
    GET {{base}}/chat/rooms?userId=<id> — list rooms
    GET {{base}}/chat/rooms/:id/unread?userId=<id>
    PATCH {{base}}/chat/rooms/:id/read Body: {"userId":"<id>"}
curl example (copy-paste) 
BASE=http://basseeyta.duckdns.org
# 1. register customer
curl -s -X POST $BASE/auth/register -H 'Content-Type: application/json' \
  -d '{"name":"Cust","phone":"01000000111","governorate":"القاهرة"}' | tee /tmp/res
TOKEN=$(cat /tmp/res | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['token'])")
echo $TOKEN

# 2. register tech
curl -s -X POST $BASE/auth/technicians/register -H 'Content-Type: application/json' \
  -d '{"fullName":"Tech","phone":"01000000112","governorate":"القاهرة"}'

# 3. create room
ROOM=$(curl -s -X POST $BASE/chat/rooms -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"clientId":"","technicianId":"01000000112","requestId":"req_demo_1"}' | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['id'])")
echo $ROOM

# 4. send message
curl -s -X POST $BASE/chat/rooms/$ROOM/messages -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"senderId":"","senderType":"user","message":"hello via curl"}'

B — Socket.IO (Postman Socket.IO, or browser)

  1. Postman Socket.IO request
    • Open Postman → New → Socket.IO (if not visible: New → More → Socket.IO)
    • Server URL: http://basseeyta.duckdns.org — keep http:// (not ws://). Postman handles upgrade.
    • Namespace: /chat (for chat), /notifications, /requests
    • Auth: click Headers/Auth → Auth type: Bearer Token or add handshake field: auth.token = <JWT>. In Postman's Socket.IO tab: Auth → add key token value eyJ.... Alternative: Headers → Authorization: Bearer <token>
    • Click Connect — you should see [socket:/chat] connected <id> in server logs (pm2 logs)
  2. Join a room
    Event: join_room — Message: "<roomId>" (string, not JSON). Use the ID from POST /chat/rooms. Click Send. Server logs: joined room:<id>
  3. Listen
    Add listener for event new_message — Postman: Add listener → Event name new_message — you'll receive:
    {"id":"...","roomId":"...","senderId":"...","senderType":"user","message":"...","createdAt":"..."} for every message in that room (including from REST).
  4. Send via socket
    Event: send_message — Message (JSON):
    {"roomId":"<roomId>","senderId":"<userId>","senderType":"user","message":"Hello from Postman"}
    → All members in room get new_message instantly. Check GET /chat/rooms/:id/messages to see persistence.
  5. Other namespaces
    • /notifications: connect, emit subscribe with "<userId>", listen notification
    • /requests: connect, emit subscribe_governorate with "القاهرة", listen for future request broadcasts (via POST /service-requests push — currently server only joins, broadcast happens on service creation via FCM; socket room is gov:<name>)
  6. Leave
    Emit leave_room with "<roomId>" to stop receiving.
Browser console alternative (no Postman) 
// paste in DevTools console on this page or any page loading socket.io
const s = io('http://basseeyta.duckdns.org/chat', {auth:{token:'<JWT>'}});

s.on('new_message', m=>console.log('new_message',m));

Troubleshooting
  • Nginx 400 / CORS: Ensure nginx/basita.conf has location /socket.io/ with proxy_set_header Upgrade and Connection "upgrade" (it does). Restart: sudo nginx -t && sudo systemctl restart nginx
  • Uses http:// not https:// — VPS is currently http://basseeyta.duckdns.org (no cert). Don't use wss://.
  • Auth ignored but logged: Server middleware logs [socket] auth failed but still connects (dev). For production, change src/socket/index.ts:19 from return next() to return next(new Error('Unauthorized')) to enforce.
  • Room not found: Socket send_message creates message even if room missing, but REST requires room. Always POST /chat/rooms first.
  • Transport: Postman and browser auto-negotiate polling → websocket. If blocked, force transports:['websocket'] but Nginx must allow upgrade.
Does it work? Yes — verified in code: src/socket/index.ts:32-73 implements /chat with join_room/leave_room/send_message → new_message broadcast, backed by in-memory store.chatMessages (and pg when configured). REST + Socket both emit via getIo(). Nginx proxies /socket.io/ correctly. Tested via smoke script: REST chat passes 6/6 checks.
